### What we're building

A **buy-planning decision workspace** for a global footwear and apparel brand that sources from several contract factories.

Each week, planners have to decide which purchase requisitions to buy now, where to make them and how to ship them. Those decisions are bounded by factory certification, capacity, minimum order and production quantities, and delivery dates. Today that evidence is spread across many spreadsheets.

Our application brings it into one place. A rule engine and an optimizer propose a plan. People make every decision, and each decision is recorded with who made it, when and why.

- **Planner:** a prioritized decision queue, rule checks, certified routes, shipping options and what-if scenarios for each order.
- **Approver:** lot-by-lot or batch approval, send-back with notes, reversible approvals, readiness checks and a recorded sign-off.
- **Executive:** modelled commercial exposure, service level, review progress and escalations, all read-only.

An assistant can explain decisions and draft proposals. It cannot record a decision or change the plan.

### Stack

Python · SciPy/HiGHS (mixed-integer optimization) · FastAPI · React + Vite · SQLite · pytest
